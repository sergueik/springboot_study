A few observations:

The connection is not hardcoded in the executable.
It's stored in a user-editable XML file.
They already anticipated multiple connections.
Notice the schema:
<connections>
    <connection>...</connection>
    <connection>...</connection>
    ...
</connections>

<currentconnection>
</currentconnection>

That isn't a one-off configuration; it's a list of named connection profiles.

<currentconnection> is empty.
That's interesting. It suggests either:
this is a default configuration,
another file stores the selected profile,
or the application chooses the first entry if none is selected.
The server name is just a string.
<server>(LocalDB)\BluePrismLocalDB</server>

Nothing about that is inherently tied to LocalDB. It could just as well be

<server>.\SQLEXPRESS</server>

or

<server>localhost</server>

or

<server>SQLSERVER01</server>

provided the rest of the code doesn't explicitly reject it.

XML Schemas for the Blue Prism file formats and follow the specification of XSD 1.1 from the W3C in 2012. It was created by hand because Blue Prism was not providing schemas at the time of the initial commit and auto-generated XSD from exiting XML files were found to lack a maintainable and comprehensible quality.
